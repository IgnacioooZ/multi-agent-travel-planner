## 实验配置

- 执行命令：`python scripts/run_pilot.py --counts 4 3 3`（再次执行会产生新的 API 费用）。
- `max_total_tokens = null`：关闭累计用量停止条件，仍统计 tokens。
- 模型请求名 `deepseek-chat`，实际返回 `deepseek-flash`，temperature 0。
- multi + MCP，角色顺序 Logistics → Activities → Planner；三个划分在独立进程执行。
- 模型调用上限 24、工具调用上限 60；研究角色分别最多 6 次、Planner 最多 12 次模型调用。
- 单次最大输出 4096 tokens，上下文字符限制 160000，模型请求超时 120 秒，SDK 不自动重试。
- 代码与提示词、任务 UID、数据版本、参数均随 manifest 和源码快照保存；除累计 token 阈值外，模型工作流配置与上一轮相同。
- 运行前 24 项测试通过，包含已累计超过旧阈值仍可继续请求模型的回归测试。

## 代表 case

UID：`e20241028160248698752`。

请求：“当前位置上海。我一个人想去杭州玩一天，预算1500人民币，请给我一个旅行规划。”

旧运行在 104784 tokens 后中止，Planner 尚未请求模型。新运行用时约 72.68 秒，累计 160769 tokens，11 次模型调用、28 次工具调用，成功保存计划。

- Logistics：4 次模型调用、4 次工具调用；输入 15127、输出 1964。
- Activities：6 次模型调用、24 次工具调用；输入 107097、输出 5045。
- Planner：1 次模型调用、0 次工具调用；输入 30370、输出 1166。

结构验证可直接定位两个火车条目各自缺少必填 `start` 与 `end`。计划中“西湖风景名胜区”被写成两个活动；交通费用也混入部分景点活动的 cost。官方评分指出重复景点、费用、时间顺序、用餐时间和位置衔接等问题。5 项硬约束中 3 项通过，全部通过为 false。

因此，本次证明累计预算曾阻止部分任务完成；它同时显示，即使允许更多调用，Planner 仍可能产生结构和约束错误。后续可分别验证结构化输出、schema 校验与有限修正、交通费用和时间核验，不应把所有改进一次混合引入。
