01 · Motivation1 / 11

Multi-agent collaboration has made major progress on complex tasks

As large language models improve, more systems no longer rely on a single model; they decompose a task across multiple role-playing agents that divide work and coordinate through conversation. Multi-agent systems have shown abilities single models struggle to match in software engineering, scientific research, reasoning, and behavior simulation. Below are representative mainstream works.

Coordination
AutoGen · MetaGPT · ChatDev · CAMELdecompose tasks across role-playing agents that complete software development and scientific research through dialogue and division of labor.
Reasoning
Du et al., 2023multi-agent debate: agents challenge and correct each other, improving factuality and reasoning.
Simulation
Park et al., 2023Generative Agents: believable social behavior emerges in a multi-agent environment.

The source of these capabilities is "role specialization + coordination." But most work reports only overall gains, and rarely evaluates "collaboration" as an isolated, controlled variable — we cannot tell whether the gain comes from collaboration itself or merely from more model calls and compute budget.

02 · Motivation2 / 11

Travel planning is an ideal testbed for evaluating collaboration

Travel planning is a classic complex decision task, naturally suited to testing multi-agent collaboration:

1
Naturally decomposable. A full itinerary involves transportation, lodging, attractions, and dining — each with its own query tools and constraints — a structure that maps well onto multiple roles.
2
Verifiable constraints. Budget, time, opening hours, and distance feasibility are hard constraints; "success" is objectively judged rather than "looks plausible," so a shared scorer can measure whether collaboration really helps.
3
Public benchmark and sandbox. ChinaTravel provides a fixed task set, a controlled database snapshot, and an offline scorer for reproducible evaluation; each task exposes only the public uid and request, while hidden constraints are used only by the scorer, avoiding leakage.
4
A gap to fill. Few works run a controlled comparison against a single agent under the same model, tools, and budget, so the benefit of collaboration is hard to attribute — the gap we want to fill.

We therefore reproduce a multi-agent travel assistant and build a single/multi controlled comparison to evaluate — and then improve — the collaboration mechanism.

03 · Questions & Contributions3 / 11

Research questions

Under the same model, tools, and budget, does multi-agent collaboration improve reliability on travel planning? How does the gain depend on task complexity and reasoning cost?

We aim to show multi-agent is useful — on simple easy tasks, single may be cheaper; on complex medium/human tasks (multi-intent, conditional/dependent booking, long dialogue), multi should show clear superiority.

09 · Failure analysis9 / 11

Two failure modes → directions for improving collaboration

multi's failures concentrate on cross-step joint-constraint problems (placeholder examples below):

#FailureSymptomCategory
1Budget/time joint planning didn't convergesatisfied budget or time, but not both.joint constraint
2Repeated-restaurant rule missedlost the "no repeated restaurant" constraint across queries.constraint miss

Neither failure is a tool or protocol problem — multiple constraints were lost or failed to converge when they had to be held simultaneously across roles and steps.

Contrast with single: single's failures are mostly budget exhaustion (ExceptionGroup) — the single agent's context grows past the request/tool budget on complex tasks; multi's failures are mostly constraint non-convergence — different failure modes (placeholder).

Direction 1

Explicit dependencies & conditions

Write "budget ≤ 1500" and "time feasible" as explicit constraints, checked before submit; booking depends explicitly on "availability query succeeded + price condition met."

Direction 2

Bounded retry verification

Add a pre-submit verification step with limited rework on failure, avoiding non-convergent joint constraints.

Direction 3

Structured hand-off

Pass structured, provenance-preserving evidence between roles to reduce constraint loss across roles.

Direction 4

One-by-one ablation

Ablate each mechanism and quantify its contribution to the pass rate.

10 · Conclusion10 / 11

Collaboration's benefit grows with task difficulty

1
More reliable on complex tasks. multi clearly beats single on medium / human (86% vs 60%, 90% vs 68%); single's failures are mostly budget exhaustion, while multi stays within budget via role division — collaboration is useful.
2
Cheaper on easy. accuracy is equal on simple tasks, but single is cheaper (~2.75× tokens, ~3× latency), so easy tasks don't need collaboration.
3
Cost–benefit holds. multi pays higher reasoning cost for a higher pass rate on medium — an acceptable trade.
4
Honest boundary. conclusions here rest on placeholder data (50 tasks per split), to be replaced with measured results; still need repeats and holdout validation.
